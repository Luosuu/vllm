## Codebase Patterns
- vLLM profiling uses `--profiler-config` JSON with keys: profiler, proton_context, proton_data, proton_hook
- SGLang profiling uses `python -m sglang.profiler` with `--proton` flag and `--proton-context`, `--proton-data`, `--proton-hook` args
- SGLang offline bench: `python -m sglang.bench_offline_throughput --model-path <model> --dataset-name random --random-input-len N --random-output-len N --num-prompts N`
- SGLang online bench: `python -m sglang.bench_serving --backend sglang --dataset-name random --random-input N --random-output N --num-prompts N`
- SGLang server: `python -m sglang.launch_server --model-path <model> --port 30000`
- vLLM environment: ~/vllm/.venv, SGLang environment: ~/sglang/.venv
- proton-viewer command: `proton-viewer -m time/ns <file.hatchet>`
- Proton CLI wrapper: `proton --context shadow --data tree --hook triton --name <name> <script.py>`
- SGLang Engine runs scheduler in a subprocess — proton in main process CANNOT see subprocess GPU kernels
- SGLang's _ProfilerProton.stop() only deactivates; finalize() is deferred to atexit which never fires (SIGKILL shutdown)
- Use `sglang.bench_one_batch` instead of `bench_offline_throughput` for Proton profiling (single-process, calls proton.finalize())
- SGLang bench_one_batch: `python -m sglang.bench_one_batch --model-path <model> --batch-size N --input-len N --output-len N --profile --profile-activities PROTON --proton-context shadow --proton-data tree --proton-hook triton`
- Reference existing vLLM profiling scripts at scripts/profiling/ for patterns
- Comparison scripts go under scripts/profiling/comparison/, output under profiling_output/comparison/
- REPO_ROOT for comparison scripts is 3 levels up from SCRIPT_DIR (comparison/ -> profiling/ -> scripts/ -> repo)
- vLLM online profiling: `vllm serve` with `--profiler-config` JSON, then `/start_profile` and `/stop_profile` POST to control window
- vLLM bench serve uses `--random-input-len`/`--random-output-len` and `--request-rate` flags
- SGLang online profiling requires `--disable-cuda-graph` to avoid CUPTI error 39 (Proton vs CUDA graph subscription conflict)
- SGLang profiler client: use `--no-cpu --no-gpu --proton` to avoid PyTorch CUDA profiler competing for CUPTI
- SGLang's _ProfilerProton.stop() was patched to call finalize() for non-persistent sessions (data otherwise never written to disk)
- SGLang graceful shutdown (kill_process_tree) uses SIGKILL — atexit/finally blocks in scheduler subprocess never fire
- SGLang bench_serving uses `--random-input`/`--random-output` (no `-len` suffix, unlike vLLM)

  - SGLANG_PROTON_CUDA_GRAPH=1 creates persistent session before graph capture (alternative approach, but data only flushes on finalize)
